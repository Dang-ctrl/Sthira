# Build the decision ledger, not another memory layer

Most of this idea already exists as separate tools. Nobody yet sells or ships the combination, but you should build only one narrow slice of it. Ingesting coding-agent sessions, searching them locally, serving context over MCP and writing CLAUDE.md/AGENTS.md files are all table stakes by October 2026. claude-mem alone has **101k stars**, and cross-agent session search already covers **31 providers** ([claude-mem](https://github.com/thedotmack/claude-mem); [claude-code-history-viewer](https://github.com/jhlee0409/claude-code-history-viewer)). Three things are still open. The first is a **personal, cross-source decision ledger** that pulls decisions out of web-chat exports, agent sessions and meeting transcripts together. The second is **contradiction warnings that cite the source of the earlier decision and run on a local open-weight model**. The third is **non-destructive supersession**, meaning old decisions are marked as replaced rather than deleted, so you can always see why you changed your mind. The closest existing tool, smm-sync, implements the record-and-check loop almost exactly. But it covers coding agents only, uses Claude Haiku as the judge, and is listed as inactive ([Glama](https://glama.ai/mcp/servers/varunajaytawde28-design/smm-sync)). That matters because research shows updating and resolving conflicting facts is the weakest area for every memory system tested: multi-hop conflict-resolution scores are **at most 7%** ([MemoryAgentBench](https://arxiv.org/html/2507.05257v3)). A demo that visibly handles "I changed my mind" is therefore a demo of the hardest open problem. The idea fits a 6-hour, 3-person hackathon if you scope it as a single-file CLI plus MCP server. It would ingest Claude Code JSONL, a ChatGPT export and a plain-text meeting transcript, extract decisions with Qwen3 through Ollama, and flag a contradiction live. The "living profile" should be a stretch goal. Long-term star potential is real but not automatic: the coding-memory niche is saturated, and breakout repos have needed a sharp hook plus tight integrations.

## The idea reduces to one loop: capture a decision, then check new work against it

Strip away the features and the core is a loop with four verbs. **Capture** scattered AI conversations, **extract** the decisions in them (what was chosen, why, what was rejected, and when), **store** each decision with provenance and a validity period, and **check** new plans, diffs and chats against what is stored, raising a cited warning on conflict. Search, the personal profile and instruction-file generation are all ways of reading that store. Framed this way the project is not "memory for AI". It is closer to "git blame for your own judgement", and that separates it from roughly 15 memory projects with more than 10k stars ([open-source survey](https://github.com/mem0ai/mem0); [Graphiti](https://github.com/getzep/graphiti); [Cognee](https://github.com/topoteretes/cognee)).

The pain is documented and specific. Claude Code users complain that conclusions from long design sessions never reach CLAUDE.md and get re-researched ([claudeissues #41313](https://claudeissues.com/issue/41313-agent-does-not-proactively-maintain-claude-md-claude-rules-after-sessions)). Old session transcripts sit on disk but the agent cannot reach them ([#59270](https://claudeissues.com/issue/59270-prior-session-conversations-inaccessible-claude-documents-decisions-incompletely)). One user wrote that sessions "waste massive tokens on trial-and-error for things already figured out" ([Unblocked](https://getunblocked.com/blog/claude-code-institutional-memory/index.md)). Practitioners argue that decisions do not belong in CLAUDE.md, because it bloats and is only advisory, and that writing ADRs (Architecture Decision Records: a short note of context, decision, rationale and rejected options) was "the habit that helped most" ([mnemehq](https://mnemehq.substack.com/p/why-claudemd-stops-scaling)). A 2026 study of coding agents adds an important warning: agents follow a stale convention file even when it prescribes worse code, so **a stale file can cost more than no file** ([arXiv 2608.16630](https://arxiv.org/abs/2608.16630)). A ledger is only worth building if superseding and expiring old decisions are core features, not afterthoughts.

## Seven adjacent categories each own one piece of the loop

The table maps every adjacent category against the four verbs. The pattern is clear. Capture and search are crowded, extraction is fragmented by source, and cross-source contradiction checking is almost empty.

Two details in the table matter for positioning. The first is that **web-chat import is underserved among large projects**. Among projects with more than 1k stars, only Basic Memory clearly imports chat exports. Everything else that does, such as agentkeeper, mychatarchive, VESTI and ctk, has fewer than 400 stars ([agentkeeper](https://github.com/Thinklanceai/agentkeeper); [mychatarchive](https://github.com/1ch1n/mychatarchive)). The only open-source tool found that unifies web chats and agent logs, hippocampus-mcp, does search with no distillation ([Glama](https://images.glama.ai/mcp/servers/hrmtz/hippocampus)). The second is that **vendor portability is shallow**. Claude and Gemini both shipped "import memory" in March 2026, but it works by copy-pasting a summary the other model writes. Gemini's ZIP import moves text only, at most 5 ZIPs a day, and launched unavailable in the EEA, UK and Switzerland ([PCWorld](https://www.pcworld.com/article/3100804/google-gemini-can-now-import-your-chatgpt-or-claude-chat-history.html); [AlternativeTo](https://alternativeto.net/news/2026/3/google-gemini-now-lets-users-import-memory-context-and-chat-history-from-other-ai-apps)). The Data Transfer Initiative concluded in March 2026 that "we aren't there yet" on a shared schema ([CDT](https://cdt.org/insights/dont-let-perfect-be-the-enemy-of-portable/)). Vendors now treat ChatGPT and Claude ZIP files as a de facto interchange format, which hands a local tool a free on-ramp.

Research systems provide the store design. Graphiti gives each fact two timelines: when it was true in the world (valid_at/invalid_at) and when the system learned or retired it (created_at/expired_at). A contradicted fact is marked invalid rather than deleted ([Graphiti docs](https://mintlify.com/getzep/graphiti/concepts/temporal-model)). Mem0 has the LLM choose ADD, UPDATE, DELETE or NOOP against similar existing memories, which loses history on delete ([survey 2512.02038](https://arxiv.org/pdf/2512.02038)). A 2026 survey of 435 works on always-on agents found the literature focuses on accumulating and retrieving state, not on governing, recovering or removing it. It treats task ledgers and commitments as first-class persistent state ([arXiv 2606.30306](https://arxiv.org/abs/2606.30306)). A personal decision ledger is a direct application of that underserved governance agenda. One caution: in Mem0's own paper, a plain full-context baseline (72.9%) beat Mem0 (66.9%) on LoCoMo ([Zep rebuttal](https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/)). For one person's small corpus, a well-structured SQLite store is enough, and graph infrastructure is optional.

## Six projects could close the gap, but each is missing a different piece

The threat list is ranked by how little each project would need to add to occupy the proposed position.

**smm-sync / Axiom Hub (MIT)** is the closest match conceptually. Agents record decisions with rationale, alternatives and constraints. `smm check` compares a new decision against the stored ones, using sentence-transformer embeddings to narrow the candidates and Claude Haiku to judge. A commit hook then offers Resolve, Defer or Ignore. Decisions live in append-only JSONL linked by SUPERSEDES/CONTRADICTS edges in a graph database ([Glama](https://glama.ai/mcp/servers/varunajaytawde28-design/smm-sync)). It validates the loop but is coding-only, needs a hosted model, and is listed as inactive. Your project should credit it openly and differ on sources and on the local judge. **projectmem** (865 stars) treats decisions as first-class events with `--supersedes`. It flags a decision as stale when the files it cites change in git, warns before a commit that repeats a failed approach, and exports to CLAUDE.md and .cursorrules. It works per repository and does **not** detect contradictions between decisions ([projectmem](https://github.com/riponcm/projectmem)). **claude-mem** (101k) already has a `decision` observation type and supports Codex, Gemini, Copilot and OpenCode. Adding a contradiction check would be a small step for it ([claude-mem](https://github.com/thedotmack/claude-mem)). **Supermemory** (31k, MIT) runs fully locally with Ollama, builds a user profile, and claims to resolve contradictions and expire stale facts. It does not import chat exports, and its contradiction mechanism is undocumented ([Supermemory](https://github.com/supermemoryai/supermemory)). **Basic Memory** (4.3k, AGPL) already imports Claude and ChatGPT exports into Obsidian-compatible Markdown with about 20 MCP tools, but has no contradiction or staleness policy ([Basic Memory](https://github.com/basicmachines-co/basic-memory)). **LongMemory** (CaviraOSS, ~4.5k) separates recorded time from valid time, applies contradiction gates during strict recall, and moves sessions between six coding agents, but has no ChatGPT import ([LongMemory](https://github.com/CaviraOSS/OpenMemory)).

Behind these sit organisation-backed hubs that already unify coding agents: memU (14.5k), EverOS (13.5k, Markdown + SQLite + LanceDB, MCP, but OpenRouter by default) and MemTensor's memmy-agent ([memU](https://github.com/NevaMind-AI/memU); [EverOS](https://github.com/EverMind-AI/EverOS); [memmy-agent](https://github.com/MemTensor/memmy-agent)). On the commercial side, Town's Leadership Decision Log is the only product found that explicitly flags a new decision as contradicting an earlier one. It is cloud-based, meeting-focused and team-oriented ([Town](https://www.town.com/routines/leadership-decision-log)). Platform vendors are the long-run risk because they control distribution. But each vendor's memory is a silo by design, and Claude Code's auto memory does not carry over to Codex, Cursor or ChatGPT ([MemoryPlugin](https://blog.memoryplugin.com/claude-code-memory/)). The open position is the intersection that none of these occupies: **cross-vendor sources plus decisions with supersession plus contradiction checks on a local open-weight model plus a personal scope**. The novelty claim is limited to that combination. "First to detect decision contradictions" would be false, and the community audits claims like that within days.

## Competitors' issue trackers show what to avoid

The most valuable prior art is the list of public failures, and it argues for a design built on boring reliability and provenance.

**Junk extraction is the main risk with small models.** An audit of 10,134 Mem0 entries found **97.8% junk**: 52.7% restated the system prompt, 5.2% were hallucinated user profiles, and one invented fact, "User prefers Vim", was stored **808 times** because recalled memories were re-extracted as new ones. A 2B local model invented a user named "John Doe" ([mem0 #4573](https://github.com/mem0ai/mem0/issues/4573)). Ollama users also hit JSON-parse failures during extraction ([mem0 #3391](https://github.com/mem0ai/mem0/issues/3391)). Benchmark evidence matches: on a JSON classification task, Llama-3.2-3B scored 0.0% because its output was malformed ([arXiv 2605.02096](https://arxiv.org/pdf/2605.02096)). Model choice also matters. Qwen3-4B-Instruct scores 87.88 on BFCL's non-live AST tests, while Gemma 3 4B and Llama 3.2 3B land around 20% overall ([datalearner BFCL](https://www.datalearner.com/ai-models/leaderboard/berkeley-function-calling-leaderboard); [benchmarklist](https://benchmarklist.com/benchmarks/bfcl/)). Prompting strategy matters more than model size ([LLMStructBench](https://arxiv.org/abs/2602.14743)). The mitigations follow directly:

- Use Qwen3-4B or 8B with schema-constrained decoding.
- Use one narrow schema per call.
- Strip system prompts and tool output before extraction.
- **Never re-extract from your own stored memories.**
- Keep a REJECT path, so the model can say there is no decision here.
- Chunk long inputs. Sending a whole hour-long transcript in one call found only 1–2 of its decisions, and chunks of about 5,500 tokens fixed this ([Convictional](https://get.convictional.com/posts/from-transcripts-to-decisions-a-research-project-in-applied-ai)).

**Fragile installs and data loss erode trust.** claude-mem's worker fails to bind its port on Windows 11, missed migrations broke it, and a version mismatch killed the worker on every event ([#380](https://github.com/thedotmack/claude-mem/issues/380); [#121](https://github.com/thedotmack/claude-mem/issues/121); [#3857](https://github.com/thedotmack/claude-mem/issues/3857)). Users also asked why it "leave[s] CLAUDE.md files literally all over" ([#609](https://github.com/thedotmack/claude-mem/issues/609)). MemPalace lost data on upgrade, suffered HNSW index corruption under concurrent writers, and broke on Python packaging ([#469](https://github.com/MemPalace/mempalace/issues/469); [#1963](https://github.com/MemPalace/mempalace/issues/1963); [#408](https://github.com/MemPalace/mempalace/issues/408)). Chroma corrupting its index on abrupt exit led one project to switch to LanceDB ([ADR-0001](https://glama.ai/mcp/servers/@camilojourney/codesight/blob/7a2e5e7f7ebc6c10653253bd035e9e16e4de11c4/docs/decisions/0001-lancedb-over-chromadb.md)). The answer is one SQLite file with FTS5, plus sqlite-vec if needed, no background daemon, and exactly one managed, marked block in each instruction file. This is also the right retrieval choice on the merits: on fact-update tasks, BM25 keyword search (48.0) beat every dense-embedding RAG setup, including Qwen3-Embedding-4B (29.0) ([MemoryAgentBench](https://arxiv.org/html/2507.05257v3)).

**Overclaiming gets punished and cloud creep breeds distrust.** MemPalace's "96.6% LongMemEval" headline helped bring in ~38k stars in a week. It then drew issues titled "Remove Baldfaced Lies Please" and "POSSIBLE SCAM REPO" once reviewers showed the number reflected raw ChromaDB retrieval and fell to 84.2% with the project's own features turned on ([agentmarketcap](https://agentmarketcap.ai/blog/2026/04/23/mempalace-memory-agent-viral-launch-benchmark-controversy); [#524](https://github.com/MemPalace/mempalace/issues/524); [#618](https://github.com/MemPalace/mempalace/issues/618)). Other projects drifted away from their open, local promises:

- claude-mem's installer prompts sign-in to a hosted observer, and its README promotes a crypto token ([claude-mem](https://github.com/thedotmack/claude-mem)).
- EverOS defaults to an OpenRouter key ([EverOS](https://github.com/EverMind-AI/EverOS)).
- Screenpipe moved from MIT to source-available and ships PostHog/Sentry telemetry on by default ([ExplainX](https://www.explainx.ai/blog/screenpipe-yc-s26-local-work-memory-agents-july-2026)).

A real OSI licence, zero telemetry and an honest, reproducible eval are differentiators in this space.

**Memory is an attack surface.** Prompt injection has written persistent instructions into ChatGPT memory (ZombieAgent, Tainted Memories), and OWASP now lists Memory and Context Poisoning as ASI06 ([WorkOS](https://workos.com/blog/ai-agent-memory-poisoning)). MINJA reaches over 95% injection success using only ordinary queries ([arXiv 2503.03704](https://arxiv.org/html/2503.03704v2)). A tool that ingests meeting transcripts and pasted documents, then serves them to every assistant, multiplies the blast radius. Every decision therefore needs four protections:

- a source span (the exact passage it came from);
- a trust tier: confirmed by the user, inferred, or from untrusted content;
- serving as quoted data, never as instructions;
- an unconfirmed status until the user approves it. This is the "commit gating" proposed in [arXiv 2601.11653](https://arxiv.org/abs/2601.11653).

## Positioning: own "decisions", leave search and generic memory to others

Pitch the project as **a local decision ledger for everything you have worked through with an AI**: "Your AIs forget what you decided. This remembers, and warns them." Do not pitch it as a universal memory layer, a profile engine or a chat search tool. The decision framing matches documented pain, has an established manual workaround (ADRs) for the tool to automate, and avoids a head-on fight with 100k-star memory projects. Avoid the name "OpenMemory": at least six projects already use it ([open-source survey, Q2](https://github.com/vancelin/openmemory)).

| Table stakes (must have, earns no points) | Differentiating (where the project wins) |
|---|---|
| Local SQLite store, no telemetry, OSI licence | One ledger across ChatGPT/Claude exports, agent sessions and meeting transcripts |
| Claude Code JSONL ingestion | Decisions as records: choice, rationale, rejected alternatives, scope, source span |
| Keyword search (plus vectors) over history | Bi-temporal supersession: what you believed on a given date, and why it changed |
| MCP server with search and context tools | `check` command: plan, diff or prompt against the ledger, giving a cited conflict warning |
| Writing a block into CLAUDE.md/AGENTS.md | Contradiction judge on a local open-weight model (Qwen3 via Ollama), not Haiku |
| Ollama/local model support | Provenance, trust tiers and a quarantine queue against memory poisoning |
| | Open, documented ledger schema with MADR export; a small published eval of extraction and contradiction accuracy |

The two-step check (cheap keyword/embedding filter, then an LLM judge) is already proven by smm-sync. What is unmeasured is **whether a 4–8B open model can serve as the judge**. No published benchmark measures decision extraction or contradiction classification for small open models on chat or agent logs ([decision research notes; VotIE](https://arxiv.org/pdf/2601.03997)). Publishing a small eval of 20–50 scripted conversations with changed decisions answers an open question. You could build the conversations by hand or generate them in the style of the synthetic FAME/MIMIC meeting transcripts ([arXiv 2502.13001](https://arxiv.org/pdf/2502.13001)). Score current-state accuracy, historical-state accuracy and false-supersession rate. This is the credible substitute for the benchmark headlines that backfired elsewhere.

The shape of the project also suits Hacktoberfest. Each source parser is a small, self-contained adapter: Cursor, Codex, Gemini CLI, Aider, Perplexity, Granola/Meetily notes and so on. That is the pattern that let ccusage grow to 16+ agent CLIs and the history viewer to 31 providers ([ccusage docs](https://www.mintlify.com/ryoppippi/ccusage/installation); [history viewer](https://github.com/jhlee0409/claude-code-history-viewer)). A `CONTRIBUTING.md` with an adapter template and a fixture file per source turns the coverage gap into a supply of good-first-issues.

### Concrete 6-hour MVP for a team of three

The stack is Python packaged for `uvx`, SQLite with FTS5 (sqlite-vec optional), Ollama running Qwen3-4B or 8B with JSON-schema output validated by Pydantic plus one retry, nomic-embed-text or EmbeddingGemma for embeddings, and the official MCP Python SDK. Split the work into three parallel lanes after a 30-minute schema agreement.

| Person | Hours 0.5–4 | Hours 4–5.5 |
|---|---|---|
| A: ingest and store | Parsers for Claude Code `~/.claude/projects/*.jsonl`, ChatGPT `conversations.json` (message tree), and plain .txt/.md meeting transcripts. Normalise into one `messages` table and index it with FTS5. Strip tool output and system prompts. | `ledger search` CLI; MADR/Markdown export of the ledger |
| B: extract and judge | Chunk to ~5.5k tokens, then extract decisions to a `decisions` table: id, statement, rationale, alternatives, scope/project, source_span, recorded_at, valid_from, valid_to, superseded_by, status (proposed/confirmed). Then the contradiction judge: FTS/embedding top-k, followed by an LLM label of duplicate, refines, supersedes, contradicts or unrelated. | `ledger check "<plan or diff>"` that prints conflicts with source citations; a 15-case mini eval |
| C: serve and demo | MCP server with `search_history`, `get_decisions(scope)` and `check_against_decisions(text)`. `ledger sync` writes a single marked block into CLAUDE.md/AGENTS.md. | README with a GIF, seeded demo data, pitch |

The demo should tell one story end to end. In a ChatGPT chat in March you chose Postgres over MongoDB "because we need joins". A meeting transcript confirms it. Today, in Claude Code, the agent proposes adding MongoDB. The MCP check fires and cites the March chat and the meeting line. You then mark the old decision as superseded and show that history is preserved rather than deleted. Leave the "living profile" (preference facts with dedupe and staleness) as a stretch goal using the same table and judge. Leave out Gemini Takeout, screen capture, a web UI, graph databases and fine-tuning entirely. Hackathon judging criteria for the Best Open-Source AI Project track were not in the research, so tune the pitch on the day. The research supports emphasising local open-weight inference, a clean licence, and contribution-ready adapters.

On star potential, expect a modest baseline and plan for a hook. An average HN exposure for AI tools yields about **+289 stars in a week** ([arXiv 2511.04453](https://arxiv.org/abs/2511.04453v1)). "Memory for Claude Code" Show HNs reliably reach 130–220 points ([HN Algolia](https://hn.algolia.com/api/v1/search?query=memory%20claude%20code&tags=story&numericFilters=created_at_i>1735689600,points>100)). Breakouts like MemPalace and Hindsight paired a striking claim with free, local, MCP-native setup in Claude Code and Cursor ([Vectorize](https://hindsight.vectorize.io/blog/2026/06/09/fastest-growing-oss-ai-memory)). SpecStory is the warning case: it captures transcripts well but sits near 1.1k stars, because raw capture is not a hook ([sourcepulse](https://www.sourcepulse.org/projects/6126752)). The value has to come from what you derive from the transcripts.

## Conclusion

The research changes the question. Building "memory for AI" in 2026 means entering a market where the ingestion and serving layers are commodities and the leaders keep stumbling on quality, reliability and honesty. The opening is a different object: a **governed record of commitments**, with provenance, validity periods and a check step, rather than a better recall engine. Both academic surveys and practitioner complaints point to the same neglected problem: knowing when something you once decided no longer holds. An open-source project wins by being the most trustworthy implementation of that one loop, not the broadest memory product.

Two non-obvious consequences follow. First, the strongest moat is the **open ledger schema and eval**, not the code. Standards bodies (DTI, AAIF) have no memory schema yet, and a well-documented, MADR-compatible decision format that other tools can emit and read gives Basic Memory, Meetily or Spec Kit users a reason to integrate rather than compete. Second, the biggest risk is **false alarms** more than missed contradictions. A checker that warns wrongly gets switched off, and a stale ledger actively misleads agents. Track the false-supersession rate from day one, require user confirmation before a decision is enforced, and ship that discipline as the product's main promise.
