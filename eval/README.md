# Evaluation

Small and honest: a hand-built scenario, a gold list, and a script anyone can rerun.

## Setup
- **Data:** [`demo/`](../demo/), a fictional project "Acme Notes" in real export formats (generated by [`scripts/make_demo_data.py`](../scripts/make_demo_data.py)):
  - two ChatGPT exports, nine conversations in total. Four of them are noise: a kitten's name, a trip, a poem, and a concept explanation.
  - one meeting transcript
  - one Claude Code session in which the agent drifts from past decisions
- **Gold:** [`gold.json`](gold.json), the 10 entries a human would want recorded (decisions, an open question, a preference, a lesson, a commitment).
- **Protocol (`sthira demo`):**
  1. Phase 1 extracts from the March export with no feedback.
  2. A simulated reviewer settles entries that match gold and rejects the rest, giving a reason (the reason becomes a rule).
  3. Phase 2 extracts from the June export and the transcript with the learned rules.
  4. Phase 3 scans the agent session for contradictions.
- **Precision** is the share of proposed entries the reviewer settled. **Recall** is the share of gold items matched by a settled entry.

## Results (laptop, Ollama, 18 Oct 2026)

| Model | Phase 1 precision (no feedback) | Phase 2 precision (with learned rules) | Recall vs gold | Agent contradictions caught |
|---|---|---|---|---|
| qwen3:4b (run 1, early prompt) | 0.40 | 0.57 | 0.60 | 2 / 2 |
| qwen3:4b (run 2, current prompt) | 0.60 | **0.71** | **0.80** | 2 / 2 |
| qwen3:8b | 1.00 | 1.00 | 0.80 | 2 / 2 |

### Contradiction checks ([`check_cases.json`](check_cases.json), `scripts/eval_checks.py`)

Three real contradictions and three non-contradictions (including two "add a cache in front of the database" traps), checked against the demo ledger.

| Model | Check pipeline | Correct | Avg latency |
|---|---|---|---|
| qwen3:4b | single pass | 4 / 6 (both cache traps flagged as contradictions) | ~15 s |
| qwen3:4b | single pass + self-correction critic | **6 / 6** | ~22 s |

The critic only runs when the first pass claims a conflict. It asks a concrete question ("does the new work stop using, migrate away from, or go against what was chosen?") and reasons before answering. In an early version that answered first and then explained, it talked itself out of real contradictions. Schema field order mattered on a 4B model.

## What this says
- The **learning loop matters most on small models.** On qwen3:4b, rules learned from rejections raised precision on unseen conversations. qwen3:8b made no extraction mistakes here, so there was nothing to learn.
- **Contradiction detection** caught both drifts in the agent session (MongoDB migration vs the Postgres decision, password login vs magic-links-only), citing the original chat.
- **Verdict self-correction:** a second "critic" pass re-examines every claimed contradiction and drops false alarms (e.g. adding a cache in front of the chosen database). User corrections of verdicts become rules for both passes.

## Limits
- One small scenario, built by the same team that built the system. Treat these as smoke-test numbers, not a benchmark.
- The reviewer is simulated (keyword match against gold), and borderline items such as merged entries are judged strictly.
- Runs are not seeded. Expect variation between runs, especially on 4B models.

Contributions of more scenarios (and real anonymised exports) are very welcome.
